## Fixed in 0.6.1

- Calendar permission requests and event reads now run inside Patter instead of its separate recording helper, so macOS can associate Calendar access with the app.
- Calendar and notification errors appear beside their controls instead of at the bottom of Settings.
- Calendar permission status distinguishes access that has not been requested, denied access, write-only access and restrictions. **Check again** refreshes the status without requesting access.
- Settings includes shortcuts to Calendar, Notifications, Microphone and Screen & System Audio permissions, plus help connecting Google calendars through Internet Accounts.
- Calendar access is requested only when connecting explicitly; starting the app does not prompt for Calendar access.
- App and recording-helper metadata are separate so test builds can use their own app identity. The production bundle identifier and recording helper identity remain unchanged.

## Connect your calendar

After updating, open **Settings → Calendar → Connect calendar**. If macOS asks, allow full access; Patter only reads your events. If access was previously denied, use **Calendar permissions** to enable Patter, then return and reconnect. Patter appears in macOS Calendar permissions after requesting access; there is no manual add button.

Google Calendar must be enabled for your Google account in macOS Internet Accounts. Check that meetings appear in Apple Calendar first. Meeting reminders still require Patter to remain running.

## Updating and verification

Use **Settings → Updates → Install and restart**, or download the DMG. Existing conversations, recordings, settings and history are retained. As with previous ad-hoc-signed updates, Google Drive may need reconnecting with your original Google Desktop OAuth setup JSON.

All 50 Rust tests and 11 frontend tests passed locally, as did the frontend build and packaged native build. Browser checks verified the revised Settings layout and expandable setup guidance without console errors. Release CI tests and builds the app, verifies its updater signature and checks uploaded artifact checksums before publication.

The actual macOS Calendar consent prompt and successful Calendar connection have not been verified end to end: native UI automation stalled during the packaged-app check. This release does not claim that final permission test passed. Patter remains a personal preview for Apple Silicon Macs on macOS 15+, without Apple notarization.
