Patter 0.6.8

System audio now uses the macOS audio-only capture API, and recording permissions refresh correctly.

- Replace ScreenCaptureKit with private Core Audio taps for computer audio, retaining a separate microphone track. No screen/window enumeration, video capture, screen permission request or screen-permission gate.
- Use System Audio Recording Only and its usage description. macOS checks that grant when you explicitly start recording. Patter no longer incorrectly labels it denied using the separate screen permission, or asks for a screen grant when audio is already enabled.
- Settings refreshes microphone status on foreground, visibility changes and Check again. Denied microphone access opens settings; restricted access cannot be requested. Concurrent checks share an in-flight read and never reuse a settled permission result or overlap a consent request.
- Preserve selected meeting linkage, chunk offsets, file finalization and the existing automatic transcript/summary pipeline. Failed starts/stops release acquired resources; partial/empty captures do not fabricate audio.
- Packaging gates require audio-only usage descriptions and Core Audio linkage without ScreenCaptureKit.

Current releases remain ad-hoc signed. Code identity changes can still require fresh microphone/system-audio/calendar grants after upgrades. This fix does not guarantee permission continuity; stable Developer ID signing needs an Apple signing identity that is not configured. No TCC reset, new credentials or permission changes are performed.

Validated with frontend/native regressions, synthetic audio file finalization and failure cleanup, mocked permission-refresh UI, builds and signed bundle inspection. Actual microphone/system-audio capture, macOS consent and upgrade permission continuity remain unverified. Existing recordings are not processed or modified automatically.

Personal preview for Apple Silicon Macs on macOS 15+. No Apple notarization.
